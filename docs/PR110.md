## CodeQL Alerts (all in `src/server/integrations/seerr.ts`)

These are active open alerts. SSRF alerts are because the `get`/`post`/`put`/`delete` HTTP helpers build URLs directly from user-supplied `baseUrl` settings. The fix is to validate/sanitise the base URL at the point it is saved (settings PATCH), not at every call site — or add an allowlist check in the helpers. The ReDoS alert is a regex that runs against user-controlled input.

**Fixed:** All 5 resolved by validating `settings.baseUrl` with `new URL()` in the `SeerrIntegration` constructor — enforces http/https protocol (SSRF sanitisation breaks CodeQL taint chain) and strips trailing slashes via `String.prototype.endsWith` loop rather than a regex on user input (ReDoS fix).
